## 1. 概述

### 1.1 编写目的

本文档说明风电功率爬坡预警系统的软件总体设计：体系结构、模块划分、数据结构（数据库设计）、接口设计、关键算法与部署运行方式，作为开发、测试、演示与后续维护的依据。

### 1.2 系统目标

以 SDWPF 公开风场数据为对象，构建"数据—事件—预测—概率化—决策—系统"一体化的爬坡预警系统，支持**离线回测**与**实时演示**双模式，输出事件级预警（方向 + 等级 + 概率 + 提前量）并提供可视化与自然语言解释。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 爬坡事件 | 给定时间窗 Δt 内功率变化超过阈值 θ 的事件 |
| 统一口径 | Δt=1h(6步)、θ=20%(40.2MW)、L=1h(6步)、H=2h(12步) |
| τ | 告警概率阈值（代价敏感标定） |
| 迟滞 | 连续 2 步超阈触发、回落 0.8τ 撤销，抑制虚警 |
| p_up/p_dn | 上/下行超阈概率 |

## 3. 数据库设计

### 3.1 选型

采用 **SQLite**（`output/wind_ramp.db`），零部署、可随系统分发，字段结构与 MySQL 兼容，可平移。

### 3.2 表结构

**表 1 `field_power`（场站功率/气象）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| t_idx | INTEGER PK | 全局步序号（10min/步） |
| day, step | INTEGER | 天序号 / 天内步 |
| p_mw | REAL | 场站总有功 (MW) |
| wspd_mean | REAL | 平均风速 (m/s) |
| wdir_sin, wdir_cos | REAL | 风向编码 |
| etmp, itmp | REAL | 环境/机舱温度 |
| cap_mw | REAL | 可用装机容量 (MW) |
| ramp_rate | REAL | 爬坡率 |
| split | TEXT | train/val/test |

**表 2 `ramp_events`（爬坡事件）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| event_id | INTEGER PK | 事件号 |
| direction | TEXT | up/down |
| start_tidx, end_tidx | INTEGER | 起止步 |
| level | INTEGER | 1/2/3 三级（按幅度） |
| delta_p | REAL | 功率变化幅度 (MW) |
| met_term, work_term | REAL | 成因分解两项 |
| cls | TEXT | 气象型/工况型/混合型 |
| is_main | INTEGER | 是否主口径（≥20%） |

**表 3 `pred_prob`（逐点预测概率）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| t_idx | INTEGER PK | 步序号 |
| p_up, p_dn | REAL | 上/下行超阈概率 |
| p_hat | REAL | 点预测功率 |
| delta_p_hat | REAL | 预测功率变化 |

**表 4 `alarm_log`（预警记录，历史可回溯）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| alarm_id | INTEGER PK | 告警号 |
| t_start, t_end | INTEGER | 告警事件起止步 |
| direction | TEXT | up/down |
| level | INTEGER | 分级 |
| tau | REAL | 触发阈值 |
| p_peak | REAL | 峰值概率 |
| matched_event_id | INTEGER | 命中的真实事件号 |
| is_hit | INTEGER | 是否命中 |
| lead_steps | INTEGER | 告警事件起点相对真实起点的步差（含负值） |

> 注：`lead_steps` 记录"合并告警事件起点 − 真实事件起点"的步差，含负值（告警略晚于真实起点属正常）；与 `event_eval` 的"提前量"口径（告警时刻经 L 平移后再算）略有差异，论文数据库设计一节已注明。

**表 5 `run_meta`（运行元数据）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| key | TEXT PK | 键 |
| value | TEXT | 值（tau/theta/L/dt/prob_source 等） |

### 3.3 索引

`field_power(t_idx)`、`ramp_events(start_tidx)`、`ramp_events(is_main)`、`pred_prob(t_idx)`、`alarm_log(t_start)`、`alarm_log(direction)`。

## 4. 接口设计

后端 `code/api_server.py` 基于 Python 标准库 `http.server` 实现 REST（零第三方依赖，语义等价 FastAPI，可无缝替换）。默认监听 `0.0.0.0:8000`，返回 JSON，`Access-Control-Allow-Origin: *`。

| 方法 | 路径 | 参数 | 说明 |
| --- | --- | --- | --- |
| GET | `/health` | - | 健康检查 |
| GET | `/meta` | - | 运行元数据（tau/theta/prob_source 等） |
| GET | `/timeseries` | t0,t1 | 功率/风速时序 |
| GET | `/prob` | t0,t1 | 逐点 p_up/p_dn |
| GET | `/events` | direction,level,main_only | 爬坡事件（可按方向/等级/主口径过滤） |
| GET | `/alarms` | direction,is_hit,t0,t1,limit | 历史告警查询 |
| GET | `/alarm_summary` | - | 告警命中汇总 |
| GET | `/alarm_explain` | alarm_id,live | **大模型**生成单条告警的自然语言解释 |
| POST | `/predict` | JSON:{window:[72步×14]或序列} | **模型调用**：在线推理 P̂/ΔP̂/p_up/p_dn |
| POST | `/predict_manual` | JSON:{wspd,p_mw?,tau?,wind_thr?,led?,save?} | **传感器闭环**：输入风速→补窗口→模型→判定→入库→LED |

## 5. 关键算法

### 5.1 概率化（残差经验分布）

复用回归模型验证集残差 e = y − P̂，偏置校正后构造经验 CDF，超阈概率：

```
P(ΔP > θ)  = 1 − F_emp(θ − ΔP̂)
P(ΔP < −θ) = F_emp(−θ − ΔP̂)
```

零额外训练成本，区间覆盖验证集 0.8041（目标 0.80），Brier 0.028–0.052。

### 5.2 代价敏感决策

```
τ* = argmin_τ (C_miss·漏警数 + C_false·虚警数)
```

代价比 1:1/5:1 取 τ*≈0.60，10:1 取 τ*≈0.20–0.25；迟滞在各代价比下降归一化代价（0.186/0.093/0.256）。

### 5.3 大模型解释（Prompt 工程 + 兜底）

输入告警事实 → 三段式 Prompt（系统角色 + 结构化事实 + JSON 输出约束）→ OpenAI 兼容接口生成 `{summary, action, reason}`；无配置时回退规则模板，保证离线可运行。

### 5.4 传感器输入闭环（输入→判断→LED）

任务书核心链路：前端输入（手动/传感器）→ 后端 → 数据库 + 模型 → 判断 → 返回前端 + 点亮单片机 LED。

**数据构造**：传感器仅测风速。后端 `build_window_from_sensor()` 以最近真实窗口为底，将末尾 6 步（1 小时）的风速置为实测值，功率按**经验风功率曲线**（SDWPF 实测分箱容量系数：≤3→0.014、3–6→0.169、6–9→0.475、9–12→0.719、12–15→0.729、15–20→0.693）派生，再按训练集 μ/σ 归一化，构成 (1,72,14) 窗口送入 reg_infer。

**双路判定**：
- 模型路（`by=model`）：p_up/p_dn ≥ τ 触发；
- 风速旁路（`by=wind`）：wspd ≥ wind_thr 直接上爬坡告警，贴合"风速传感器达阈值即报警"。

**结果落库**：确实预警且 `save=true` 时写 `alarm_log`（source='manual'），返回 `alarm_id`。

**LED 下发**：`led_bridge.py` 通过串口向下位机发送 `LED:ON\n` / `LED:OFF\n`（环境变量 `LED_SERIAL_PORT` 指定 COM 口，默认 9600bps）；无硬件时降级为虚拟 LED，`real_hardware=false`，不影响整条链路演示。
